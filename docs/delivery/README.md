## Что готово сейчас

- production-нода напрямую принимает три обязательных топика организаторов;
- fixed-lag watermark принимает запаздывающие колесные timestamp, а наружу публикуется
  current-time prediction;
- математическое ядро не зависит от ROS и использует идентифицированный YAML-профиль;
- поддержаны запуск без GNSS, начальная привязка и периодические GNSS-коррекции;
- положение переводится из along-track `s` в continuous MGRS по Pathgraph;
- публикуются скорость, положение, ускорение, covariance, wheel health и диагностика;
- подготовлены replay, Failure Lab, отчёты, API и интерфейс демонстрации;
- Python-проверка этой итерации: `113 passed`, `10 skipped`; отдельно ROS/Humble:
  `30 passed` (8 integration + 22 core/fixed-lag);
- лабораторный Docker-образ собирается и запускает `demo`; веб-код в этой итерации не менялся;
- автоматический rosbag-прогон и независимый GNSS-scorer сохраняют воспроизводимые артефакты.
- исправлено преждевременное восстановление залипших каналов; на test при двойном
  залипании RMSE скорости снизилась с 1,462 до 0,274 м/с, пути — с 43,33 до 4,70 м;
  методика, небольшие регрессии и оставшиеся ограничения — [FREEZE_VALIDATION.md](FREEZE_VALIDATION.md).

Пропущенные на хосте тесты — восемь ROS/Humble (проверены отдельно в контейнере) и два
opt-in API. Таблицы `dataset/derived` пересозданы, real-data тесты больше не пропускаются.

Основной режим соответствия условию — `gnss_policy=disabled`: в нём GNSS не поступает в
алгоритм и используется только offline как эталон точности. Остальные политики являются
дополнительными режимами для начальной привязки и исследования периодических коррекций.

## Что обязательно сделать перед сдачей

1. Повторить [автоматическую проверку](RUN.md) на финальной машине жюри и приложить artifacts.
2. Для абсолютного положения предоставить правильные `route_id/s0` или гарантировать,
   что начальное GNSS-окно находится на карте. Относительная одометрия — не XY-трек.
3. Явно раскрыть слабость при одновременном залипании колёс и некалиброванность covariance.
4. Расширить независимые длительные ROS-прогоны и измерение задержки со стороны источника.
5. Сверить типы с финальным окружением жюри. Проверено использование:
   `/result/velocity` — `tram_vehicle_msgs/msg/VelocitySensor`, `/result/position` —
   `nav_msgs/msg/Odometry`.

## Вердикт

Обязательный ROS-контур собран и проверен на реальных данных, расхождения лаборатории и
runtime исправлены. Это проверенный прототип хакатона, а не сертифицированная навигация:
общий отказ колёс и абсолютная привязка вне карты остаются существенными ограничениями.
Последние числа, методика и границы проверки — [FREEZE_VALIDATION.md](FREEZE_VALIDATION.md).
Предыдущий полный check-bag — [RUNTIME_VALIDATION.md](RUNTIME_VALIDATION.md).
