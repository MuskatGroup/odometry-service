## Что готово сейчас

- production-нода напрямую принимает три обязательных топика организаторов;
- fixed-lag watermark принимает запаздывающие колесные timestamp, а наружу публикуется
  current-time prediction;
- математическое ядро не зависит от ROS и использует идентифицированный YAML-профиль;
- поддержаны запуск без GNSS, начальная привязка и периодические GNSS-коррекции;
- положение переводится из along-track `s` в continuous MGRS по Pathgraph;
- публикуются скорость, положение, ускорение, covariance, wheel health и диагностика;
- подготовлены replay, Failure Lab, отчёты, API и интерфейс демонстрации;
- Python-проверка на текущем коммите: `89 passed`, `6 skipped`; frontend production build проходит.

Пропущенные тесты — два ROS/Humble, два opt-in API и два теста, которым нужен
`dataset/derived`. Это не считается подтверждением полного production-прогона.

Основной режим соответствия условию — `gnss_policy=disabled`: в нём GNSS не поступает в
алгоритм и используется только offline как эталон точности. Остальные политики являются
дополнительными режимами для начальной привязки и исследования периодических коррекций.

## Что обязательно сделать перед сдачей

1. Запустить Docker Desktop или Ubuntu 22.04 с ROS 2 Humble и выполнить ROS-тесты из
   [`BUILD.md`](BUILD.md).
2. Пересоздать `dataset/derived` и выполнить benchmark на validation/test без GNSS и с
   `initial`/`intermittent-60` по [`VALIDATION.md`](VALIDATION.md).
3. Запустить именно `reserve_odometry_node` на одном полном rosbag организаторов, записать
   `/result/velocity`, `/result/position`, `/odometry/estimate` и `/odometry/diagnostics`.
4. Зафиксировать p99 задержки, CPU, RSS, долю валидного времени и ошибки относительно
   GNSS-reference. Проверить лимиты на целевой машине.
5. Подтвердить с организаторами точные ROS-типы выходов. Сейчас принято:
   `/result/velocity` — `tram_vehicle_msgs/msg/VelocitySensor`, `/result/position` —
   `nav_msgs/msg/Odometry`.

## Вердикт

Функциональная реализация ожидаемых блоков готова. **Полностью готовым к сдаче решение
станет после целевого ROS/rosbag-прогона и фиксации измеренных результатов.** До этого
корректная формулировка — «код готов, интеграционная и эксплуатационная приёмка открыта».
