# Точность и быстродействие

## Методика

Production-нода запускалась в ROS 2 Humble на предоставленном
`tests/check-code/bags/30618_88aea4d9` с `ros2 bag play --clock --rate 1`.
Контейнер ограничен 2 CPU и 512 МиБ. API и web выключены.

Проверенный участок начинается с `+230 с`, где маршрут покрыт Pathgraph. Одна точка
эталона задаёт допустимые начальные `route_id`, `s0` и `v0`. После запуска:

- `gnss_policy=disabled`;
- нода не создаёт GNSS-подписок;
- `/localization/kinematic_state` получает только независимый checker;
- сопоставление выполняется по Header stamp с допуском 50 мс;
- позиционная ошибка — евклидово расстояние между MGRS XYZ.

Исходные параметры старта:

```yaml
route_id: shchukinskaya_to_tallinskaya
s0_m: 76.70021572499135
initial_v_mps: 8.264238620430273
start_offset_s: 230
```

## Offline test split

Профиль `30618.yaml` идентифицирован по 35 train-bag и проверен на отдельных validation
и test-bag. На 11 отложенных test-bag модель дала RMSE скорости 0,7098 м/с против
2,3695 м/с у model-only/hold baseline. Эти числа относятся к offline-методике и не
смешиваются с официальным ROS-прогоном выше.

## Проверка отказов

Автоматические тесты покрывают:

- одиночные slip, spike, freeze и dropout;
- общий freeze обоих колёс и переход в `MODEL_ONLY`;
- hysteresis и reacquisition;
- отсутствие расходимости covariance;
- задержанные сообщения, дубликаты и детерминированный порядок событий;
- отсутствие GNSS, начальную GNSS-привязку и GNSS outlier.

Ограничение: в check-bag нет подтверждённой разметки физических проскальзываний, поэтому
официальный прогон подтверждает устойчивость, но не полноту классификации каждого типа.
