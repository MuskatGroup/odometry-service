# Математическая модель

## 1. Структура

Это нелинейная gray-box модель, а не нейросеть. Физическая структура задана
уравнениями, параметры и таблицы идентифицированы offline на разрешённых train-bag.

Входы:

- нормализованная команда контроллера `u = position / 15`, `u∈[-1;1]`;
- скорости передней и задней тележек `v_w = velocity_kmh / 3.6`;
- уклон `grade(s)` из Pathgraph;
- опциональные GNSS-коррекции, если это разрешено политикой запуска.

Состояние EKF:

```text
x = [s, v, a_act, d]ᵀ
```

`s` — координата вдоль маршрута, `v` — продольная скорость, `a_act` — состояние
привода после динамического лага, `d` — медленное суммарное возмущение.

## 2. Тяговый привод

Для тяги и торможения используются отдельные двумерные таблицы:

```text
a_cmd = table_traction(u, v),  u > 0
a_cmd = table_braking(u, v),   u < 0
a_cmd = 0,                     u = 0
tau · da_act/dt = a_cmd - a_act
```

Между узлами применяется билинейная интерполяция, за границами — ограничение
ближайшим узлом. Таблица задаёт удельную продольную силу, уже делённую на
эффективную массу: `a_cmd = F_wheel / m_eff`.

Эквивалентный момент привода связан с этой величиной выражением

```text
M_motor = m_eff · a_cmd · r_eff / (i_gear · eta)
```

В текущей реализации отдельные `m_eff`, `r_eff`, `i_gear` и `eta` не оцениваются:
их совместное влияние идентифицировано непосредственно в таблице ускорения. Это
устраняет ненаблюдаемую декомпозицию при доступных входах, но означает, что нода
не публикует физический момент двигателя как отдельную величину.

## 3. Продольная динамика

```text
ds/dt = v
dv/dt = a_act - c1·v - c2·v·|v| - g·grade(s) + d
dd/dt = w_d
```

`c1` описывает линейное сопротивление, `c2` — квадратичное сопротивление,
`g·grade(s)` — влияние уклона. Переменная `d` с ограниченной амплитудой объединяет
изменения массы, качения, кривых, погоды и остаточную ошибку модели.

Интегрирование выполняется ограниченными подшагами. Скорость ограничена `v≥0`.

## 4. Измерительные обновления

```text
колёса / GNSS velocity: H = [0, 1, 0, 0]
GNSS along-track:       H = [1, 0, 0, 0]
```

Используется scalar EKF update и Joseph form для covariance. Для одинакового времени
порядок детерминирован: control → wheels → GNSS velocity → GNSS position → публикация.
Fixed-lag очередь принимает реальные задержки сообщений и не откатывает уже закрытую
историю.

## 5. Проскальзывание и отказы

Для каждого канала вычисляется состояние:

```text
normal | positive_slip | braking_slide | frozen |
dropout | inconsistent | unknown
```

Признаки: свежесть, производная колёсной скорости, innovation относительно модели,
расхождение тележек и знак команды. Hysteresis и несколько успешных обновлений нужны
для повторного захвата. Один плохой канал исключается независимо. Если непригодны оба,
фильтр переходит в `MODEL_ONLY`, увеличивает covariance и после настраиваемого горизонта
помечает оценку недействительной.

## 6. Выход

- продольное ускорение: полный правый член `dv/dt`;
- скорость: состояние `v`;
- along-track положение: интеграл скорости `s`;
- MGRS XYZ и yaw: проекция `s` на направленный Pathgraph с учётом базы тележек 7,55 м;
- covariance, режим качества и диагностика колёс.
