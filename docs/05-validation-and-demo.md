# Проверка гипотезы и демонстрация

## 1. Что считаем доказательством

Нужны одинаковые входы для сравниваемых алгоритмов, независимый эталон для оценки и тестовые поездки, не использованные при настройке. Главный результат — таблица ошибок скорости/пути и доступности оценки по типам отказов с воспроизводимыми конфигурациями.

GNSS/IMU/эталон можно использовать офлайн для проверки только при разрешении организаторов. В runtime они не поступают в оцениватель. Если доступна лишь та же колесная одометрия, независимую точность на участках ее проскальзывания доказать нельзя; тогда отдельно показываем синтетическую проверку и согласованность на реальных данных.

## 2. Baseline и последовательные эксперименты

| Вариант | Назначение |
|---|---|
| `B0 wheel + hold` | Использовать колесную скорость, при пропуске удерживать последнюю; интегрировать путь |
| `B1 model-only` | Та же физическая модель и начальное состояние, без колесных коррекций |
| `B2 fixed-EKF` | Модель с обычным слиянием и фиксированными настройками, без адаптивного контроля отказов |
| `M1 robust-EKF` | Контроль качества колес, изменение доверия и режимы деградации |
| `M2 adaptive` | `M1` плюс оценка меняющегося возмущения `d` |
| `M3 optional` | `M2` плюс адаптация коэффициента или ограниченная нелинейная поправка |

Во всех вариантах одинаковы начальная привязка, единицы, данные и интервалы оценки. Если каналов несколько, политика агрегации baseline фиксируется заранее. В `B1`, `B2` и `M1` среднее `d` фиксировано на одинаковом калиброванном значении; в `M2` разрешено его обновление при надежных колесах. Остальные параметры при сравнении `M1/M2` сохраняются, чтобы эффект адаптации не смешивался с изменением детектора.

## 3. Сценарии

Числа ниже — иллюстративные настройки синтетического стенда; их диапазоны уточняем по реальному трамваю и данным.

| Сценарий | Воздействие | Что проверяем |
|---|---|---|
| Чистый цикл | Разгон, выбег, торможение, остановка | Базовая ошибка и ложные тревоги |
| Буксование одного колеса | Завышение скорости на 30–80% в течение 1–5 с | Отбрасывание отдельного канала |
| Общее буксование | Все каналы завышены, включая плавный рост ошибки | Ограничения обнаружения, чрезмерную уверенность |
| Юз | Колесная скорость падает вплоть до нуля при ненулевом движении | Отсутствие ложного подтверждения остановки |
| Dropout | Пропуски на 1, 5, 15 и 30 с | Рост ошибки по горизонту model-only |
| Зависание | Постоянное значение с продолжающимися timestamp | Отличие от легитимного равномерного движения |
| Изменение нагрузки | Коэффициент тяги меняется между поездками/сегментами | Пользу и устойчивость адаптации |
| Неизвестный уклон | Дополнительное ускорение, в том числе во время dropout | Предел прогноза и калибровку неопределенности |
| Время и транспорт | Jitter, дубликаты, перестановки, пауза и сброс clock | Причинность и отсутствие двойной коррекции |
| Отказ ручки | Просроченное управление | Переход к недействительной оценке по timeout |
| Отказ стенда | API недоступен, UI медленный | Независимость одометрии от демонстрационного контура |

Комбинированные сценарии обязательны: например, изменение уклона во время общего буксования. Один детектор может пройти простые тесты и провалить именно такой случай.

## 4. Данные без утечки

1. Разделять train/validation/test по целым поездкам или независимым сценариям и seed, а не случайным соседним строкам одной записи.
2. Калибровать параметры на train, выбирать пороги на validation, test запускать после фиксации конфигурации.
3. Передавать ядру только причинно доступные входы. Симметричное сглаживание с будущими отсчетами нельзя использовать в онлайн-алгоритме.
4. Скрывать от ядра параметры симулятора, эталон, расписание отказов и будущую ручку.
5. Проверять на физике с другими задержками, нелинейностями и параметрами, чем у наблюдателя. Совпадающие уравнения допустимы для unit-тестов, но слабы как доказательство качества.
6. Для каждого сценария использовать несколько seed и показывать распределение результатов. Стартовый ориентир — 10 seed; финальное число зависит от времени и стоимости испытаний.

## 5. Метрики

| Метрика | Определение/смысл |
|---|---|
| Ошибка скорости | MAE, RMSE, p95 абсолютной ошибки, м/с |
| Ошибка пути | MAE по времени и ошибка в конце эпизода, м |
| Дрейф на отказе | Ошибка приращения пути от начала до конца отказа, м |
| Дрейф по горизонту | Ошибки скорости и пути через 1/5/15/30 с после потери надежных колес |
| Доступность | Доля времени с `valid=true`, доля в каждом режиме |
| Детектор | Precision/recall и задержка обнаружения по истинным интервалам отказов |
| Восстановление | Время возврата к достоверному слиянию, скачок скорости при возврате |
| Неопределенность | Эмпирическая доля ошибок в диапазоне `estimate ± 1.96*sigma`, отдельно по режимам |
| Быстродействие | p50/p95/p99/max расчета, транспортной задержки и периода публикации; пропуски дедлайна |

Для неравномерных отсчетов агрегировать ошибки с учетом времени либо на общей согласованной временной сетке. Начальный сдвиг координаты выравнивается один раз одинаково для всех; каждый эпизод отказа не получает скрытой новой привязки.

Не исключать сложные интервалы молча: публиковать ошибку всех конечных прогнозов и отдельно валидных, долю времени без прогноза и покрытие `valid`. Так алгоритм не может «победить», отказавшись выдавать результат почти везде.

`±1.96*sigma` — номинальный 95%-диапазон при гауссовом допущении, не доказанный защитный интервал. При систематическом недопокрытии корректируем модель неопределенности и снижаем доверие; не рисуем узкую полосу только для красивого графика.

## 6. Внутренние критерии принятия гипотезы

Предварительно, до получения критериев жюри:

- На заранее определенном наборе коротких отказов 1–5 с медианная ошибка приращения пути у `M2` хотя бы на 20% ниже `B0`; сравнение с `B1/B2` показывает вклад каждого компонента.
- На чистом test-наборе RMSE скорости ухудшается не больше чем на 5% либо на 0.02 м/с — используем более мягкий из двух допусков, чтобы околонулевой baseline не создавал бессмысленный процент.
- Выигрыш точности не достигается резким сокращением валидного времени; долю доступности обязательно приводим рядом.
- Сохраняется конечность состояния, корректная обработка времени и отсутствие фиктивной остановки в сценарии юза.
- На согласованном устройстве измерен бюджет из архитектурного документа; без замеров быстродействие считается непроверенным.

Это экспериментальные ориентиры, а не нормы для реального беспилотного трамвая. Абсолютно допустимую ошибку и время резервной работы определяют условия трека и потребитель одометрии.

Если преимущество не подтверждается, фиксируем результат: оставляем наиболее устойчивый вариант, показываем область применимости и объясняем, какие данные или допущения нужны для улучшения. Не настраиваемся на финальный test задним числом.

## 7. Демонстрация на 3–5 минут

1. **Нормальное движение:** ручка, колесная скорость, модельная скорость и эталон идут на общей оси времени.
2. **Буксование/юз:** колесная кривая отклоняется, режим меняется, видно, как изменяется доверие.
3. **Полное выпадение колес:** прогноз продолжается; неопределенность и накопленный путь показаны рядом с baseline.
4. **Возврат колес:** скорость возвращается к слиянию, накопленная ошибка пути не скрывается.
5. **Предел решения:** длительный отказ или неизвестное возмущение приводит к росту неопределенности и `INVALID`.
6. **Итог:** таблица по всему test-набору, частота и задержки на названной машине, команда запуска ROS-пакета.

На экране достаточно четырех синхронизированных блоков: ручка; скорости с диапазоном; ошибка пути; режим и задержка. Для одномерного MVP используем шкалу пути, а не карту города с вымышленными координатами.

Тезис для защиты: «Используем физику реакции на управление, корректируем ее достоверными колесами, ограниченно адаптируемся к условиям и явно показываем, когда резервной оценке уже нельзя доверять».
