## Быстрый старт (Windows PowerShell; на Linux то же с `export`)

```powershell
$env:PYTHONPATH = "$PWD\src"
python -m unittest discover -s tests                                   # 84 теста, около 3 с
python -m odometry_io.bench --output work/bench --seeds 3              # сценарии отказов, минута
python -m odometry_io.probe examples/input.csv --write work/profile.json
python -m odometry_io --source examples/source-csv.json --output work/run --estimator model
```

Runtime использует только стандартную библиотеку Python 3.10+. Все 84 теста проходят на 3.14.6 (Windows) и на 3.10.12 (Linux, контейнер `ros:humble-ros-base`). Выходной каталог должен быть пустым; `work/` в `.gitignore`.

ROS 2 (Ubuntu 22.04 + Humble или Docker-образ `ros:humble-ros-base`; Docker в Windows проверен):

```bash
cd ros2_ws && colcon build && source install/setup.bash
export PYTHONPATH=/path/to/repo/src:$PYTHONPATH        # ПОСЛЕ сборки, до нее ломает CMake
ros2 launch odometry_node estimator.launch.py config:=src/odometry_node/config/example.json
```

Проверка bag-replay в контейнере: [ros2_ws/tools/bag_replay_check](../ros2_ws/tools/bag_replay_check/README.md).

## Когда придут данные: порядок действий

1. **Посмотреть формат.** Для файла: `python -m odometry_io.probe data.csv --write work/profile.json` даст черновик профиля и список TODO (радиус колеса, единицы, значения ручки нужно подтвердить по описанию организаторов). Для ROS: узнать типы и топики (`ros2 bag info`, `ros2 topic list -t`), заполнить `inputs` и профиль в конфигурации моста; путь поля вида `wheels.0.omega`, время берется из `header.stamp` (`stamp_source`).
2. **Сначала baseline.** Запустить `--estimator hold` и убедиться, что единицы, время, порядок каналов и смысл ручки верны: скорость правдоподобна, путь растет, `timestamp` монотонны. Только потом `--estimator model`.
3. **Откалибровать модель** (`kt`, `kb`, `tau_s`, `c1`, шумы) по чистым участкам данных. Сейчас параметры стартовые; без калибровки модель по ручке уходит на десятки и сотни метров (см. docs/13), и весь выигрыш дает коррекция колесами. `--model-config params.json` принимает переопределения.
4. **Проверить пороги.** `control_timeout_s` (сейчас `null`: ручка удерживается) задать по реальной частоте ручки; `freeze_s`, `freeze_min_accel`, `gate_normal`, `reacquire_s` пересмотреть; решить, включать ли `adapt_disturbance` (см. ниже).
5. **Если есть эталон:** `--truth` и `--faults` дают метрики docs/05; если эталона нет, доказать нельзя ничего, кроме внутренней согласованности (`accuracy=null`).
6. **Решить по C++:** если жесткое реальное время обязательно (docs/02, п. 6), Python-ядро придется переносить; замер p99 шага сейчас 0.26 мс на ядре без ROS, на целевом железе не измерялся.

## Принятые решения

- `adapt_disturbance=false` по умолчанию: на синтетике (train и holdout) фильтр с фиксированным `d` дал меньшую сумму ошибок, чем с адаптацией; переоценить на реальных данных.
- Гейт колес использует ограниченную дисперсию (`gate_sigma_cap`) и повторное захватывание (`WHEEL_REACQUIRED`) после `reacquire_s` без принятых обновлений, иначе оценка «схлопывается» на блокировку колес; захват делает обычное полное EKF-обновление (перезапись `v` портила `a_act`).
- Слияние колес: медиана каналов, дополненная голосованием каждого канала относительно прогноза модели (`channel_gate`).
- Timestamp хранится целым числом наносекунд; float-время отклоняется. Нет тихого совмещения часов: разные часы нужно явно привести в адаптере.
- `sigma_*` считаются из ковариации, но не откалиброваны; в `reason_codes` всегда `UNCERTAINTY_UNCALIBRATED`. Пропуск измерения — не ноль.
- Работа с git: ветка `first-iteration`, в `main` не слито.

## Известные ограничения

- **Общее буксование** всех колес не обнаруживается и не исправляется (предел наблюдаемости, docs/01); с одним каналом любое буксование колеса общее.
- Все проверки точности **на синтетике**, эмулятор построен на близких уравнениях. Настоящая точность на трамвае неизвестна. Пороги детекторов выбраны без реальных данных.
- Профиль не разделяет сообщения одного топика по значению поля (`wheel_id` в `WheelSample`): нужен отдельный топик на канал или массив в одном сообщении. Пары `sec/nanosec` вне ROS-моста не читаются.
- `LiveSession.ingest` и оценщик могут применить часть пакета до исключения: при ошибке останавливать запуск, не продолжать ту же сессию.
- Детектор зависания срабатывает только когда по ручке ожидается изменение скорости; зависание при постоянной скорости он не видит (и почти не влияет на путь).
- Нет: адаптации `kt/kb`, нелинейной поправки, привязки к карте маршрута, реверса, инициализации на движущемся трамвае из внешнего источника (есть только `initialize` по контракту).
